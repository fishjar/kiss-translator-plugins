# PaddleOCR 1.0.0 验收记录

## 1.0.1 配置升级

- 在 Chrome 2.2.6 预览中导入新包并升级 1.0.0 的现有实例。实例保留自定义名称、Token、PP-OCRv5 模型及额外下载来源，并自动填入官方接口地址。识别合成图片时，真实 PP-OCRv5 调用在约 2.7 秒后返回两行文字和两组坐标。
- Chrome 的已安装列表正确展示四个更新包的名称和标签。PaddleOCR 显示新图标与「限额免费」，Index-Translate 显示「免费」，OpenRouter 和 SiliconFlow 显示「部分模型免费」。自定义网关的提交、轮询和下载由真实宿主 Broker 配合本地测试响应验证。

## AI Studio 云端验收

使用带标题、段落、表格和公式的合成 PNG 实测。时间从提交到下载结果，记录每个模型首次成功的尝试。

| 模型 | 结果 | 耗时 |
| --- | --- | --- |
| PP-OCRv6 | 11 个文字行，每行有多边形 | 78.3 秒 |
| PP-OCRv5 | 11 个文字行，每行有多边形 | 3.1 秒 |
| PP-OCRv5-latin | 11 个文字行，每行有多边形 | 0.9 秒 |
| PaddleOCR-VL-1.6 | 标题、正文、表格、公式及坐标 | 19.1 秒 |
| PaddleOCR-VL-1.5 | 标题、正文、表格、公式及坐标 | 90.7 秒 |
| PaddleOCR-VL | 多次轮询达到 100 秒上限，未加入首发模型菜单 | 超时 |
| PP-StructureV3 | 标题、正文、表格、公式及坐标 | 0.9 秒 |

PP-OCRv5-latin、PaddleOCR-VL-1.5 和 PP-StructureV3 的首次尝试超时，复测成功。结果下载地址用了多个 BOS 来源。Manifest 声明经核对的 `paddleocr-store` 及编号 1 至 9 的北京 BOS 来源。下载使用预签名地址，不附加 Token。

## 扩展传输与离线验收

- Chrome 的扩展来源头触发 HTTP 403。使用主机现有按来源声明的 Origin 重写后，探测请求到达官方鉴权层。重写仅作用于官方任务 API 来源。
- 本地 Chrome 预览扩展和文件翻译站点通过真实云端调用。用 PP-OCRv5 验证文字行坐标，用 PaddleOCR-VL-1.6 验证网页图片、截图、文件图片和 PDF 图片区域的识别，随后用 Microsoft 翻译验证标题、正文和表格内容，并核对公式保留。PDF 使用 Fast 模式解析后手动识别图片区域。
- 浏览器测试使用当时的开发预览包。当前插件声明 API 2。其他浏览器未纳入本次验收。
- 离线用真实包读取器、Sval、Broker 和宿主结果校验验证混合坐标块、跨页回退、域名权限和 API 版本兼容性。协议测试另覆盖表格、公式、无效 JSONL、任务失败和整体超时。
